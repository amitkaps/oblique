Oblique

Do Chrome, Firefox and Safari match font-style (normal, italic, oblique, slnt) the way CSS Fonts 4 says? A reference implementation of the spec decides what each case should do; the browsers are tested against it.

Test coverage: @font-face descriptor × use-site CSS

One font, one glyph under test: real Cairo (slnt −11..11), subset to the letters of OBLIQUE, tested on the capital I. Columns (A, B, C…) are what the @font-face declares; rows (1, 2, 3…) are the CSS at the use site, and a cell is its column letter plus its row number. What each cell should do is not decided by hand: an independent JavaScript implementation of CSS Fonts 4 font-style matching (reference/) computes it, and never uses a browser to do so. Every cell states what the reference expects. Where the spec pins the outcome down (“spec: slnt −11”) the cell is a WPT test for that one rendering; where it leaves latitude (“spec*: slnt 0 / synth”) the test only forbids what the spec forbids; where it is silent, the cell is only observed. font-synthesis is left at its default in rows 1 to 9, since synthesis should apply only when a face is missing; rows 10 to 12 set it on purpose. Each specimen is live in your browser: pink is a rendering the spec accepts, cyan is the CSS under test; aligned they blend pale, and visible pink is a failure. The circles are recorded results: Chromium and Firefox from wpt run, Safari from a direct safaridriver replay (wpt run proved unreliable on Safari). Candidate for upstreaming; no WPT PR has been opened.

Findings

Cells A2, A3, A5 and A8 (italic, bare oblique, <em> and oblique 45deg against a face declared oblique -11deg 11deg, default synthesis): the axis must clamp to −11 and nothing may be synthesized on top. Firefox does that. Chrome stacks a synthetic skew on the axis (36px lean, expected 16px). Safari stacks for bare oblique and oblique 45deg, and gives a pure synthetic skew, no axis at all, for italic and <em>. Rows 10 and 11 repeat rows 2 and 3 with synthesis off and pass everywhere, so the failure is the extra skew and nothing else.

Cell C12: italic with font-synthesis-style: oblique-only against a face declared normal must stay upright (a synthesized oblique must not stand in for italic). Firefox does; Chrome and Safari synthesize.
